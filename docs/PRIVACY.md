# 数据、缓存与模型费用

## 数据流

前端向 Host 提交会话 ID（重新生成另带 `force`）。Host 从 DSH 读取会话，构造预测上下文，通过 `ctx.llm.stream` 调用模型。插件不保存单独的 API 密钥文件，没有独立遥测服务器。

**这不等于对话不会离开本机。** 预测上下文发送到所选 provider，其保留和训练政策由该服务决定。覆盖 provider/model 时，预测可能使用与原会话不同的服务。

默认 `clean` 仅选取 user/assistant 文字，按消息数和字符预算裁剪，不转发工具 schema；文字本身仍可能含敏感信息，插件不自动脱敏密钥。

`cache`／`prefix` 在预算内使用 `session.deriveMessages()` 原始数组，可能包含系统提示、工具历史及原生消息携带的其他内容，不应视为精简纯文本模式。超出前缀预算回退到 `clean`。字符预算不等于 token、附件字节或费用上限。

## 模型与费用

默认继承会话 provider、model、reasoning effort，不自动选择廉价模型。正常轮次完成、进入需要预测的已完成会话、重新生成或重试，都可能产生额外调用。缓存和去重减少重复请求，供应商前缀命中仍由供应商决定。取消请求不保证供应商停止计算或免计费。

预测不写入会话事件，也不进入会话 token 用量账本。请用供应商记录或订阅额度核对实际消耗。插件默认启用；不希望自动调用时关闭开关。

## 本地保留

| 数据 | 存储与生命周期 |
| --- | --- |
| Host 结果 | 内存 LRU，最多 100 项，10 分钟 TTL |
| 前端建议 | 内存，最多 40 个会话，建议 10 分钟 TTL |
| 接受／忽略状态 | 前端内存，绑定轮次和配置，受会话容量约束 |
| 最近原因与耗时 | 内存，界面只显示清洗后的原因 |
| 使用计数 | localStorage 的 `dsh-composer-predictions.stats.v1`；设置中可重置 |
| 开关和人工配置 | DSH profile，由 DSH 设置服务管理 |

计数只包含 shown/accepted/regenerated，不含正文、会话、模型或提示词，也不发送到独立分析端点。进程／页面退出会清除所属内存缓存。

## 调试与反馈

保持 `debug: false`。开启时，未解析模型输出的前 1200 个字符可能出现在 Host 日志和调试响应，可能包含对话信息。分享前检查；优先使用合成会话复现。

文档预览由隔离夹具生成，不采集用户桌面。卸载不删除 DSH 会话和登录。计数清理方法见 [安装与卸载](INSTALL.md)。
